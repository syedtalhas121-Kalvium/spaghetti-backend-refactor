# Clean Sweep Backend Refactor

This project refactors the original monolithic Express and Prisma backend into a layered architecture without changing the API contract.

## Architecture

```text
Request
  -> routes/
  -> controllers/
  -> services/
  -> Prisma
  -> SQLite database
```

The `app.js` entry point is limited to Express initialization, JSON middleware, route mounting, and server startup. Route modules define endpoint paths and delegate immediately to controllers. Controllers coordinate request and response handling. Services contain the business logic and all Prisma database operations.

## Project Structure

```text
.

```

## Local Setup

```bash
npm install
npx prisma generate
npx prisma db push
npx prisma db seed
npm start
```

The API listens on port `3000`.

## Endpoint Inventory

| Method | Endpoint | Purpose |
|---|---|---|
| GET | `/users` | Return active users with posts and `fullName` |
| GET | `/users/:id` | Return one user with posts |
| POST | `/users` | Create a user |
| DELETE | `/users/:id` | Deactivate a user |
| GET | `/posts` | Return published posts with authors |
| GET | `/posts/:id` | Return one post with its author |
| POST | `/posts` | Create an unpublished post |
| PATCH | `/posts/:id/publish` | Publish a post |

## Zero-Regression Verification

All eight endpoints were exercised before and after the refactor using the same seeded SQLite database snapshot and the same request sequence. Status codes, response shapes, persisted fields, and business behavior matched for every request. Seven endpoint responses matched byte-for-byte; the only intentional runtime difference was the `createdAt` timestamp generated by SQLite for the newly created post, because the two independent runs execute at different times. This timestamp is produced by the unchanged Prisma schema and is not controlled by the route, controller, or service refactor.
